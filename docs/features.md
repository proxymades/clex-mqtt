## Проверяемые сценарии MQTT 5

- Receive Maximum = 1: следующий QoS 2 PUBLISH отправляется после PUBCOMP; отрицательный PUBREC освобождает квоту. PING обрабатывается во время ожидания подтверждений.
- Topic Alias: создание, повторное использование, переназначение и новый набор соответствий при переподключении. Нулевой или превышающий лимит alias получает код `0x94`, неизвестный alias при пустом топике – `0x82`.
- Maximum Packet Size: пакет на точной границе лимита принимается; превышение распознаётся по заголовку и получает код `0x95`.
- Properties: повтор одиночного свойства получает `0x82`, свойство другого типа пакета – `0x81`. Повторяемые User Properties сохраняют порядок.
- Совместные подписки: отдельная копия каждой группе, чередование участников, переподключение, QoS 2, проверка прав по внутреннему фильтру, лимиты очередей и точный UNSUBSCRIBE. Сохранённые сообщения передаются при дальнейших публикациях; начальная выдача retained относится к обычным подпискам.
- SCRAM-SHA-256: эталон RFC 7677, вход через AUTH, подтверждение сервера, повторная аутентификация без смены сессии, обмен MQTT во время проверки, неверный пароль, смена пользователя, повтор proof, отзыв учётных данных и таймауты. Ошибки начальной аутентификации сохраняют базу без новой сессии и Will.

Тесты отправляют самостоятельно сформированные MQTT-пакеты через TCP в отдельной схеме тестовой PostgreSQL. Протокольная база: [MQTT 5.0 OASIS Standard](https://docs.oasis-open.org/mqtt/mqtt/v5.0/os/mqtt-v5.0-os.html).

## Критерии следующих этапов

1. Расширить независимую MQTT-совместимость, включая ограничения MQTT 5, ошибки свойств и переполнение очередей.
2. Проверить аварийное завершение процесса на переходах QoS и при фиксации БД, потерю БД, заполнение диска и резервное восстановление.
3. Расширять граничные сценарии MQTT 5 и совместимость мостов с внешними брокерами; клиентские сертификаты исходящего моста и QoS 2 выделены в отдельные расширения.
4. Измерить задержки, скорость маршрутизации и использование ресурсов на целевых профилях нагрузки.
5. Проверить production-пакет в отдельном staging-окружении перед первым промышленным запуском.

Конечная цель сохраняется: полнофункциональный брокер с собственной панелью. Промежуточный выпуск не обозначается как полная замена Mosquitto.

Для совместных подписок назначенные QoS 1/2 закрепляются за выбранной сессией. Перенос незавершённой QoS 1 доставки другому участнику после завершения сессии относится к следующему этапу.
